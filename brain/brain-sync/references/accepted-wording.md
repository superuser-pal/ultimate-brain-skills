# Accepted wording (Documents, Reports; decision 0054, spec/cli.md §5.14.7)

The whole mechanism of accepted wording, steps 1 to 9. SKILL.md's Pull, Apply and Push steps and other skills name these steps as brain-sync "Accepted wording" step N.

Notion Brain Assistant writes a promoted Document's body or a report's proposed refresh inside Notion. Only text the user **accepted** (the **Accept** button on Documents ticks **Accepted** and sets **Accepted at**; Accept write-up and Accept refresh before 0.9.1) comes back to Git, exactly. This section is the whole mechanism; brain-catch-up orders it.

1. **Which pages.** With Documents on, the promoted Documents; with Reports on, the Report rows (Documents, Origin Report, a `vw-` Brain ID; on the Inbox with Kind Report in a space not yet on migration 0019). Choose them from Git: the Documents are the index's `reference` notes whose file has `origin: promoted`, the reports its `view` notes with `view_kind` report. `since` = the earliest `last_synced` among them, minus 2 minutes; if any has no `last_synced`, or no `notion_published["@notion_body"]` or `["@git_body"]` (never published, published before 0.8.0, a baseline lost), there is no `since`. Then select the rows whose **Accepted** is ticked **or** whose last edit is at or after `since` (all of them when there is no `since`), and keep those whose Brain ID is one of the chosen notes:
   - **From the Documents rows you read in Pull step 2,** when it read every row (Documents is on) and that read is complete (you followed `next_cursor` from the first page until it was null and every page came back; a page that failed and was read again with its own cursor counts) and you have Brain ID (an empty one counts), Accepted and `last_edited_time` for every row. Don't query Documents again.
   - **Otherwise query the Documents database** with that filter (no filter when there is no `since`), following `next_cursor` to the end: when the read stopped before the end, or you didn't read one of the three on some row. Never take a partial read as the whole: a row on a page you didn't read could be a draft to protect.
   - In a space not yet on migration 0019, **always query the Inbox rows of Kind Report** this way: Pull step 2 doesn't read every one of them with its Accepted box.

   Use only rows read in this run, never an earlier run's (spec/cli.md §5.14.7). This changes which rows you select, not what you read: step 2 below still reads each selected page, and the re-reads before apply and publish stay.
2. **Read each page** and put its row, with a `wording` object, in `rows.json` (Pull step 3, formats.md): `accepted`, `accepted_at`, `page_edited_at` (the page's `last_edited_time`), `pending_revision` (a toggle titled exactly "Proposed revision" is on the page), `pending_refresh` (a toggle titled exactly "Proposed refresh · based on Notion"), and `body_markdown`.
3. **Convert the body** to Markdown, leaving out the two toggles above: paragraph → its text; headings → `#`, `##`, `###`; bulleted and numbered items → `- ` and `1. ` (nested by two spaces); to-do → `- [ ]`/`- [x]`; quote → `> `; callout → `> ` plus its icon and text; toggle → `<details><summary>title</summary>` and its children; code → a fenced block with its language; divider → `---`; link → `[text](url)`; bold, italic, strikethrough, inline code → `**`, `*`, `~~`, `` ` ``; a page or database mention → `[title](notion-page:<page id>)`. Join blocks with one blank line; end with exactly one newline. A block this list does not name (embed, synced block, table, column) means you set `unconvertible: true` and `body_markdown: null`; never guess. Never trim or "tidy" the text.
4. **Plan, then show.** The plan holds the arrays `accepted_wording`, `wording_waiting`, `wording_held` and `clear_accepted`. Attended: for each `accepted_wording` item show the user the exact change as a diff of the whole file (the Git body against `markdown`) with its Document or report and `diff` counts, and import after a yes (a no leaves the page accepted and the Git body unchanged; say "skipped"). Name each `wording_waiting` row with its reason in plain words ("edited after you accepted: click Accept again", "a Proposed revision is still on the page", "accepted but has no time: click Accept again", "emptied page") and each `wording_held` of `UNACCEPTED_DRAFT` or `UNCONVERTIBLE_BLOCK` not at all (they only stop a publish from overwriting the page).
5. **Verify, then apply.** Just before `sync apply`, re-read every `accepted_wording` page (the same fields, `body_markdown` converted again). If Accepted is no longer ticked, `Accepted at`, `page_edited_at` or the fingerprint of `body_markdown` differs from the item's, or a proposal toggle appeared, drop the item and put it on the Needs you line as "changed since I looked: click Accept again". Otherwise add `"verified": { "fingerprint": <the item's>, "page_edited_at": <the item's> }`. Then `sync apply` (brain-sync step 6) imports the survivors. An item the CLI fails (`UNVERIFIED`, `GIT_CHANGED`, `INVALID_REPORT_SHAPE`, `KIND_MISMATCH`, `NOTION_ID_MISMATCH`) goes on the Needs you line with its reason; nothing was written for it.
6. **After a publish or an import, record the read-back.** After you write a Document's or report's body (create, or a refresh) and after an import, read the page back once, convert it as in step 3, hash the text with `shasum -a 256` on a file holding exactly those bytes, and add `"@notion_body": "sha256:<hex>"` to that page's record (formats.md). (The page's body is the one thing you read back after writing: the CLI needs it, because what Notion returns is not byte-equal to what was sent.)
7. **Clear Accepted** for each `clear_accepted` item and each applied `accepted_wording` item: re-read the page; only if Accepted is still ticked with the **same** Accepted at, the same `page_edited_at`, no proposal toggle, and a body that hashes to the item's `fingerprint`, untick Accepted and clear Accepted at through the MCP. Otherwise leave the page alone; the next run plans it afresh. Skip a `clear_accepted` entry the CLI dropped (a failed update, a conflicted row).
8. **Rows with no baseline** (attended only), both states: a `wording_waiting` `NO_BASELINE` row (the page is **accepted**) and a `wording_held` row with reason `NO_BASELINE` (not accepted). Show Notion's text beside Git's as a full diff: the page is a Document or report published before 0.8.0, or its baseline was lost. **Adopt Notion** is offered only on the accepted one, which has a real Accepted at: after the user confirms the diff, **add to `plan.json`'s `accepted_wording`** (before the single apply of Pull step 6) the item you build yourself (`kind`, `note`, `page_id`, `accepted_at` and `page_edited_at` from the snapshot, `fingerprint` = the hash of `body_markdown`, `markdown`, `base` = the hash of the Git body now, `unattended_ok` false, `diff`), verify it as step 5, and apply it. On a page that is not accepted, say: "click Accept, then catch up again". **Adopt Git:** never rewrite a Notion body; show the Git text for the user to paste into the page. Record nothing; the next run finds them equal and records the baselines itself.
9. **Publish.** `sync render --changed --plan plan.json` already holds the body of every note named by a waiting, held or accepted row (`skipped`, `WORDING_PENDING`): never work around it, and never write a body to a page that row names. **Only the text waits** on a page that is not accepted (every row naming it has `"accepted": false`): its item still comes with its properties (Origin, Project, Area, Asked in…) and `body: null`; write those properties, read nothing back and add no `@notion_body`. An accepted page gets no item at all: any write would move its edit time and make the Accept look stale.

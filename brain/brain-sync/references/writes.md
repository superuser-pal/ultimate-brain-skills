# Writing render's items through the MCP (SKILL.md Push step 10)

The cases of step 10 beyond a plain `create` or `update`: what to do with each item that has one of these keys or states. Step 10's other rules in SKILL.md (parallel writes, the one read-back, final content, `pending_relations`) apply to all of them.

- **`template` on a project `create`** (decision 0068): list the Projects data source's templates once per run (`GET /v1/data_sources/{id}/templates`). With a default template, create the page with `"template": { "type": "default" }` and the item's `properties`, and no children: the template supplies the page. Then re-read its blocks a few times, over about 30 seconds, until the "Brief" and "Decision log" toggle headings are there, and write `sections` into them. Never append toggles to a page you just created from the template; if they don't appear, or a section write fails, record the page with `"@content": null` in its `published`, so the next run sends the sections. With **no default template**, create nothing for that project, record nothing for it, and ask the user to create it with **New project** in Notion and put the note's id in its Brain ID; notes that relate to it are written without that relation this run. Status is the user's: the report names each new project so they can set it.
- **`action: trash`** (a draft page from before 0.9.1, `--unpublish-drafts` only, decision 0071): move `page_id` to Notion's trash (update the page with `in_trash: true`; `archived: true` on API versions before 2025-09). Nothing else. Record it like any other write.
- **Documents · Origin missing** (decision 0071): when the Documents data source has no **Origin** property, leave Origin out of the write and out of the `published` you pass to `sync record`, and say in the report: "Documents has no Origin yet: run notion/migrations/0018-concepts-become-documents.md or 0019-reports-move-to-documents.md (either adds it)". Write the rest of the item as usual; the first render after the migration sends Origin (spec/cli.md §5.14.4).
- **`body` on Inbox items** (a source's digest): the brain-ingest skill's references/notion.md, "Inbox bodies". **A report's `body`** (on its Documents row, also on a refreshed report's `update`): the same file, "Report bodies". Never write a capture's or an Ask row's page body; render never gives one.
- **`sections` (projects):** replace only the children of the toggle heading with that exact name ("Brief", "Decision log"). Read the page's blocks first (decision 0033):
  - **the page has no toggle headings at all** (created without the template): append a "Brief" and a "Decision log" toggle heading, in that order, at the end of the page, then fill them;
  - **the page has other toggle headings but not this one:** report `SECTION_NOT_FOUND` for that page and change nothing on it (a rename is likely, 0026).
- **`sections` (areas, decision 0041):** the "Brief" toggle; a page without one gets it appended at the **end** of the page, then filled.
- **How to write a section:** through the **block API only**, never the Markdown page update, which flattens toggles on a page that has content (decision 0043): the brain-ingest skill's references/notion.md, "Writing a section through the MCP".
- **`"mode"` on a property:** `"add"` adds pages and keeps the existing ones. `"if_empty"` writes only to an empty property: read the property first, and leave it as it is when it holds anything. It is on Meeting and Inbox relations, and on an Inbox row's **Kind**, so a Kind the user chose stands (decision 0048). Never write a meeting's Name, Date or body (0007).
